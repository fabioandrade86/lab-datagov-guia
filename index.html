Dados não estruturados com Databricks, Fabric e Purview

Guia prático para montar um lab, entender o porquê de cada decisão e levar a arquitetura a um cliente: PDFs, imagens, Word e PowerPoint são ingeridos e extraídos no Azure Databricks, governados no Unity Catalog, consumidos no Microsoft Fabric sem cópia e protegidos com Microsoft Purview.

Arquitetura alvo

Um documento entra como arquivo bruto, vira texto e campos estruturados no Databricks, aparece no Fabric sem cópia e é protegido nos dois lados.

Fatos que mudam o desenho

FATO Permissões não atravessam

As políticas e permissões do Unity Catalog não são espelhadas no Fabric. A credencial usada para criar a conexão do mirroring é usada em todas as consultas. Se for a sua conta de admin, o Fabric enxerga tudo o que você enxerga.

FATO Firewall no storage contorna filtros

Com trusted workspace access para ADLS atrás de firewall, o Fabric lê o storage diretamente. Nesse caminho, RLS/CLM ou ABAC do Unity Catalog não são aplicados.

FATO Sem cópia, somente leitura

O mirroring do catálogo traz metadados e lê os dados via shortcut. Tabelas ficam somente leitura no Fabric e precisam ser Delta. Exige external data access no metastore e EXTERNAL USE SCHEMA.

FATO Purview tem duas metades

Segurança de dados (rótulos, DLP, Audit, Insider Risk) segue integrada ao Fabric. Governança (Data Map, Unified Catalog) está em aposentadoria, consolidando no Fabric.

Checklist do ambiente

  1. Account console Databricks · Workspaces
    Acesse https://accounts.azuredatabricks.net, clique em Workspaces e localize . Leia a coluna Metastore. um nome de metastore. Workspaces criados após 09/11/2023 são habilitados para Unity Catalog automaticamente.
  2. Account console · Catalog · (metastore) · Configuration
    Anote Metastore Admin, ADLS Gen 2 path, auto-assign de workspaces e OpenSharing. Na aba Workspaces, veja quantos workspaces dividem o metastore. em metastore criado automaticamente, o Metastore Admin pode estar vazio. Isso é normal, mas afeta o M6 (external data access é ligado por metastore admin).
  3. Account console · User management · Groups
    Procure os grupos , e . os grupos só aparecem se existirem no Entra ID e estiverem sincronizados com a conta Databricks.
  4. Workspace Databricks · Catalog · ⚙ · Metastore · Details
    Veja se a opção External data access aparece e está ligada. desligada por padrão. Se a opção nem aparece, você não tem privilégio para alterá-la.
  5. Workspace Databricks · SQL Warehouses
    Veja se já existe um warehouse e qual é o auto-stop. se existir, auto-stop curto (10 min ou menos). Não crie ainda; o dimensionamento fica para o M1.
  6. Portal do Fabric · Configurações · Admin portal / Capacity settings
    Confirme se existe capacidade (F SKU ou trial) e se você pode criar o workspace . sem capacidade não há mirroring. Recursos como trusted workspace access e pause/resume exigem F SKU.
  7. Portal do Purview · Settings · Roles / Licenças no Microsoft 365 admin
    Verifique se há licença para rótulos e DLP no Fabric (M365 E5, E5 Compliance, E5 Information Protection & Governance ou Purview capacities) e se você tem papel de Compliance/Information Protection admin. sem licença, o M7 vira proteção só por Unity Catalog e OneLake security.
  8. Portal Azure · Workspace Databricks · Networking
    Veja se o acesso público ao front-end está habilitado, se há VNet injection e private endpoints. com rede aberta o mirroring funciona direto; com private endpoint precisa de VNet data gateway (M9).
  9. Portal Azure · Resource group · Tags
    Confira as tags obrigatórias (projeto, ambiente, owner, expira). Se a tag expira estiver vencida, atualize antes de investir tempo no lab. se houver automação que remove recursos expirados, o lab pode sumir.

Perguntas de checagem
  1. Por que o Unity Catalog é pré-requisito de quase tudo neste lab?
    Volumes, AI Functions sobre arquivos, grants e o mirroring para o Fabric dependem de um workspace ligado a um metastore.
  2. Qual metade do Purview entra neste projeto e por quê?
    Segurança de dados (rótulos, DLP, Audit). A governança (Data Map, Unified Catalog) está em aposentadoria e não aceita contas novas.
  3. O que um Metastore Admin vazio significa e quando passa a importar?
    Metastore criado automaticamente. Importa quando é preciso ligar external data access ou transferir posse de objetos de terceiros.
  4. Que pergunta de rede você faz antes de prometer mirroring?
    O workspace tem private endpoint / acesso público desligado? Se sim, precisa de VNet data gateway.

M1Unity Catalog na práticaDatabricksCUSTO
Objetivo
Hierarquia catálogo → schema → tabela/volume; managed vs external; storage credential e external location; grants por grupo.
Analogia
Prédio (catálogo) → andar (schema) → salas (tabelas e volumes). A chave de um andar não abre outro, e para entrar numa sala é preciso também poder entrar no prédio e no andar (USE CATALOG, USE SCHEMA).
Custo
Rodar SQL liga um SQL Warehouse ou cluster. Use o menor tamanho e auto-stop curto.
FATO Boas práticas oficiais

Atribua papéis de admin e posse de objetos a grupos. Metastore admin é opcional: atribua só se precisar. Cuidado com ALL PRIVILEGES: ele não inclui MANAGE, EXTERNAL USE LOCATION nem EXTERNAL USE SCHEMA.

  1. Databricks · SQL Warehouses
    Crie (ou use) um warehouse Serverless do menor tamanho, auto-stop de 5 a 10 min. status Running em poucos segundos. Ele para sozinho após o tempo ocioso.
  2. Databricks · SQL Editor
    Rode o bloco abaixo para criar catálogo e schemas. o catálogo aparece no Catalog Explorer. Se o metastore não tem storage raiz, o CREATE CATALOG pede MANAGED LOCATION.
  3. Databricks · SQL Editor
    Aplique os grants por grupo e transfira a posse para o grupo admin. SHOW GRANTS mostra só grupos, nenhum usuário individual.
  4. Catalog Explorer · catálogo · Workspaces
    Avalie restringir o catálogo a este workspace (workspace-catalog binding). por padrão, catálogos são acessíveis de qualquer workspace ligado ao metastore.
Databricks · SQL Editor
-- 1) Catálogo do lab.
--    Se o metastore NÃO tem storage raiz, descomente MANAGED LOCATION
--    (o caminho precisa estar coberto por uma external location).
CREATE CATALOG IF NOT EXISTS {{CATALOG}}
  -- MANAGED LOCATION 'abfss://lab@{{STORAGE}}.dfs.core.windows.net/{{CATALOG}}'
  COMMENT 'Lab de dados não estruturados (Databricks + Fabric + Purview)';

-- 2) Camadas do medalhão
CREATE SCHEMA IF NOT EXISTS {{CATALOG}}.raw    COMMENT 'Pouso de arquivos brutos (volumes)';
CREATE SCHEMA IF NOT EXISTS {{CATALOG}}.bronze COMMENT 'Inventário de arquivos';
CREATE SCHEMA IF NOT EXISTS {{CATALOG}}.silver COMMENT 'Conteúdo extraído (ai_parse_document)';
CREATE SCHEMA IF NOT EXISTS {{CATALOG}}.gold   COMMENT 'Campos de negócio e tabelas de consumo';

-- 3) Posse para o grupo admin (nunca para uma pessoa)
ALTER CATALOG {{CATALOG}} OWNER TO `{{GRP_ADMIN}}`;

-- 4) Engenharia: lê e escreve em todas as camadas
GRANT USE CATALOG ON CATALOG {{CATALOG}} TO `{{GRP_ENG}}`;
GRANT USE SCHEMA, CREATE TABLE, CREATE VOLUME, SELECT, MODIFY
  ON SCHEMA {{CATALOG}}.raw    TO `{{GRP_ENG}}`;
GRANT USE SCHEMA, CREATE TABLE, SELECT, MODIFY ON SCHEMA {{CATALOG}}.bronze TO `{{GRP_ENG}}`;
GRANT USE SCHEMA, CREATE TABLE, SELECT, MODIFY ON SCHEMA {{CATALOG}}.silver TO `{{GRP_ENG}}`;
GRANT USE SCHEMA, CREATE TABLE, CREATE FUNCTION, SELECT, MODIFY
  ON SCHEMA {{CATALOG}}.gold TO `{{GRP_ENG}}`;

-- 5) Leitura: só a gold (princípio do menor privilégio)
GRANT USE CATALOG ON CATALOG {{CATALOG}} TO `{{GRP_READ}}`;
GRANT USE SCHEMA, SELECT ON SCHEMA {{CATALOG}}.gold TO `{{GRP_READ}}`;

-- 6) Conferência: quem acessa o quê
SHOW GRANTS ON CATALOG {{CATALOG}};
SHOW GRANTS ON SCHEMA {{CATALOG}}.gold;

Managed vs external, em uma frase

  • Managed: o Unity Catalog decide onde guardar e governa todo acesso. Ao apagar, o dado é removido (volumes managed retêm 7 dias). Padrão recomendado.
  • External: você aponta um caminho existente. Útil quando outro sistema também lê ou escreve ali, mas esse sistema pode contornar o Unity Catalog.
  • Storage credential guarda a identidade (managed identity do Access Connector) e a external location liga essa identidade a um caminho ADLS.
Perguntas de checagem
  1. Um usuário tem SELECT numa tabela da gold mas não consegue consultar. O que falta?
    USE CATALOG no catálogo e/ou USE SCHEMA no schema.
  2. Por que transferir a posse do catálogo para um grupo?
    O dono pode conceder qualquer privilégio. Se a pessoa sair, a administração não fica órfã.
  3. ALL PRIVILEGES no schema gold libera o mirroring para o Fabric?
    Não. EXTERNAL USE SCHEMA não está incluído e precisa ser concedido explicitamente.
  4. Quando você escolheria um volume external?
    Quando outro sistema (por exemplo, um app do cliente) deposita arquivos naquele caminho e você quer governar o acesso pelo Databricks.
No cliente

Peça o resultado de SHOW GRANTS nos catálogos de produção. Grants para usuários individuais, ALL PRIVILEGES espalhado e catálogos com dono pessoa são achados de governança imediatos.

M2Volumes e ingestão de arquivosDatabricksCUSTO
Objetivo
Guardar e listar arquivos não estruturados com controle de acesso e montar a bronze de inventário.
Analogia
O volume é um arquivo morto com fechadura do Unity Catalog. A bronze é o livro de protocolo: registra cada documento que entrou (o quê, tamanho, impressão digital, quando).
Dados
Use amostras sintéticas: contratos fictícios, notas fiscais de exemplo, laudos gerados, fotos sem pessoas. Inclua de propósito um PDF escaneado ruim, um DOCX, um PPTX e uma imagem.
  1. Databricks · SQL Editor
    Crie o volume de pouso e conceda acesso. o volume aparece em Catalog Explorer › {{CATALOG}} › raw › landing.
  2. Catalog Explorer · volume landing · Upload to this volume
    Suba 10 a 20 arquivos sintéticos (PDF, JPG/PNG, DOCX, PPTX). os arquivos aparecem listados com tamanho e data.
  3. Databricks · SQL Editor
    Liste os arquivos e crie a bronze de inventário. uma linha por arquivo, com extensão, tamanho e hash SHA-256.
Databricks · SQL Editor
-- 1) Volume managed de pouso (o Unity Catalog decide o caminho físico)
CREATE VOLUME IF NOT EXISTS {{CATALOG}}.raw.landing
  COMMENT 'Pouso de documentos sintéticos do lab';

-- 2) Engenharia lê e escreve arquivos; leitura NÃO acessa o bruto
GRANT READ VOLUME, WRITE VOLUME ON VOLUME {{CATALOG}}.raw.landing TO `{{GRP_ENG}}`;

-- 3) Lista o conteúdo do volume
LIST '/Volumes/{{CATALOG}}/raw/landing/';

-- 4) Bronze: inventário SEM guardar o binário (evita duplicar storage)
CREATE OR REPLACE TABLE {{CATALOG}}.bronze.inventario_arquivos AS
SELECT
  path                                                  AS caminho,
  lower(regexp_extract(path, '\\.([A-Za-z0-9]+)$', 1)) AS extensao,
  length                                                AS tamanho_bytes,
  modificationTime                                      AS modificado_em,
  sha2(content, 256)                                    AS hash_sha256,
  length > 100 * 1024 * 1024                            AS acima_limite_parse,
  current_timestamp()                                   AS inventariado_em
FROM read_files('/Volumes/{{CATALOG}}/raw/landing/', format => 'binaryFile');

-- 5) Visão rápida do acervo
SELECT extensao, count(*) AS qtd, round(sum(tamanho_bytes)/1024/1024, 2) AS mb
FROM {{CATALOG}}.bronze.inventario_arquivos
GROUP BY ALL ORDER BY qtd DESC;

-- 6) Duplicados pelo hash (mesmo documento com nomes diferentes)
SELECT hash_sha256, collect_list(caminho) AS caminhos, count(*) AS copias
FROM {{CATALOG}}.bronze.inventario_arquivos
GROUP BY hash_sha256 HAVING count(*) > 1;
FATO Volume managed vs external

Managed: armazenado no storage gerenciado do schema, todo acesso passa pelo Unity Catalog e o apagamento tem retenção de 7 dias. External: registrado sobre um caminho existente; ao apagar o volume, os dados ficam no storage, e ferramentas externas podem usar URIs diretos.

Para ler arquivos é preciso USE CATALOG + USE SCHEMA + READ VOLUME; para gravar, também WRITE VOLUME.

Perguntas de checagem
  1. Onde o arquivo de um volume managed fica fisicamente?
    No storage do seu Azure (managed location do schema/catálogo/metastore), num caminho escolhido pelo Unity Catalog.
  2. Por que a bronze guarda o hash e não o binário?
    Detecta duplicados e alterações sem duplicar storage; o binário já está no volume.
  3. O grupo de leitura deveria ter READ VOLUME em raw.landing?
    Não. O bruto pode ter PII; o consumo deve vir da gold.
M3Extração com IADatabricksCUSTO
Objetivo
Transformar documentos em dados: ai_parse_document na silver, ai_extract na gold, validação visual.
Analogia
ai_parse_document é o digitalizador que entende o layout (títulos, tabelas, figuras). ai_extract é o analista que lê e preenche um formulário que você definiu.
Requisitos
Databricks Runtime 17.3+ ou serverless (ambiente 3+). Região com suporte (East US 2 tem). Custo registrado no produto AI_FUNCTIONS.
FATO Limites do ai_parse_document

Formatos: PDF, JPG/JPEG, PNG, TIFF, DOC/DOCX, PPT/PPTX. Máximo de 500 páginas (use pageRange acima disso) e 100 MB por arquivo. Documentos com assinatura digital podem não ser processados com precisão. Imagens com alfabetos não latinos podem ter desempenho pior. A REST API limita a 100 páginas por documento.

  1. Databricks · SQL Editor
    Rode a silver em poucos arquivos primeiro (custo por documento). uma linha por arquivo com o VARIANT parsed; arquivos com problema têm error_status preenchido.
  2. Databricks · Agents / Document Parsing
    Abra a UI de Document Parsing e compare o documento original com o resultado. regiões do documento destacadas com o conteúdo extraído; tabelas em HTML.
  3. Databricks · SQL Editor
    Crie a gold com ai_extract (versão 2.1, com confiança por campo). campos tipados; null quando não encontrado; score de confiança entre 0 e 1.
  4. Databricks · SQL Editor
    Separe os documentos que falharam ou têm baixa confiança para revisão humana. uma fila de exceções. É ela que mostra ao cliente a qualidade real.
Databricks · SQL Editor · Silver
-- Silver: parse do documento. Comece com LIMIT para controlar custo.
-- descriptionElementTypes = '' desliga a descrição de figuras (mais barato).
CREATE OR REPLACE TABLE {{CATALOG}}.silver.documentos_parseados AS
SELECT
  path AS caminho,
  ai_parse_document(
    content,
    map('version', '2.0', 'descriptionElementTypes', '')
  ) AS parsed,
  current_timestamp() AS processado_em
FROM read_files('/Volumes/{{CATALOG}}/raw/landing/', format => 'binaryFile')
WHERE length <= 100 * 1024 * 1024   -- respeita o limite de 100 MB
LIMIT 5;                             -- remova depois de validar

-- Texto corrido por documento + status de erro
CREATE OR REPLACE TABLE {{CATALOG}}.silver.documentos_texto AS
SELECT
  caminho,
  concat_ws('\n\n',
    transform(
      try_cast(parsed:document:elements AS ARRAY<VARIANT>),
      e -> try_cast(e:content AS STRING)
    )
  ) AS texto,
  parsed:error_status AS erro
FROM {{CATALOG}}.silver.documentos_parseados;
Databricks · SQL Editor · Gold
-- Gold: campos de negócio com ai_extract 2.1 (aceita o VARIANT do parse)
CREATE OR REPLACE TABLE {{CATALOG}}.gold.documentos_campos AS
WITH extraido AS (
  SELECT
    caminho,
    ai_extract(
      parsed,
      '{
        "tipo_documento":  {"type": "enum", "labels": ["contrato", "nota_fiscal", "laudo", "outro"]},
        "numero_documento":{"type": "string", "description": "Número ou identificador do documento"},
        "data_documento":  {"type": "string", "description": "Data de emissão no formato AAAA-MM-DD"},
        "valor_total":     {"type": "number", "description": "Valor total em reais"},
        "contraparte":     {"type": "string", "description": "Nome da empresa ou pessoa contratante"}
      }',
      map('version', '2.1', 'enableConfidenceScores', 'true')
    ) AS r
  FROM {{CATALOG}}.silver.documentos_parseados
)
SELECT
  caminho,
  r:response:tipo_documento:value::STRING            AS tipo_documento,
  r:response:numero_documento:value::STRING          AS numero_documento,
  try_cast(r:response:data_documento:value::STRING AS DATE) AS data_documento,
  r:response:valor_total:value::DECIMAL(18,2)        AS valor_total,
  r:response:contraparte:value::STRING               AS contraparte,
  r:response:valor_total:confidence_score::DOUBLE    AS conf_valor,
  r:error_message::STRING                            AS erro_extracao
FROM extraido;

-- Fila de exceções para revisão humana
CREATE OR REPLACE VIEW {{CATALOG}}.gold.v_fila_revisao AS
SELECT * FROM {{CATALOG}}.gold.documentos_campos
WHERE erro_extracao IS NOT NULL OR conf_valor < 0.7 OR tipo_documento IS NULL;
Custo

Cada documento processado consome AI Functions. Para estimar, rode em 5 arquivos, consulte system.billing.usage (M10) e extrapole pelo volume do cliente. Reprocessar tudo a cada execução é o erro mais caro: o M4 resolve isso.

Perguntas de checagem
  1. Um PDF de 800 páginas falha. Duas saídas?
    Usar pageRange em blocos de até 500 páginas, ou dividir o arquivo antes do parse.
  2. Por que manter a fila de revisão?
    LLMs erram; a fila mede a qualidade e cria o processo humano para exceções.
  3. Qual opção reduz custo quando o documento tem muitas figuras?
    descriptionElementTypes = ''.
  4. Onde o dado é processado durante o parse?
    Dentro do perímetro de segurança da Databricks; os parâmetros não são armazenados.

-- Bronze incremental: só arquivos novos (checkpoint automático)
CREATE OR REFRESH STREAMING TABLE bronze_documentos AS
SELECT path, modificationTime, length, content, current_timestamp() AS ingerido_em
FROM STREAM(read_files('/Volumes/{{CATALOG}}/raw/landing/', format => 'binaryFile'));

-- Silver incremental: parse só do que entrou agora
CREATE OR REFRESH STREAMING TABLE silver_documentos
TBLPROPERTIES ('pipelines.externalMetadata.enabled' = 'true')  -- visível ao mirroring do Fabric
AS SELECT
  path AS caminho,
  ai_parse_document(content, map('version', '2.0', 'descriptionElementTypes', '')) AS parsed,
  current_timestamp() AS processado_em
FROM STREAM(bronze_documentos)
WHERE length <= 100 * 1024 * 1024;
FATO Pipelines e o Fabric

Materialized views e streaming tables só aparecem no mirroring do Fabric com external data access habilitado para pipelines (propriedade pipelines.externalMetadata.enabled). Sem isso, a gold de um pipeline "some" no Fabric.

INFERÊNCIA Bronze com binário

A bronze incremental guarda o content para alimentar a silver. Em volumes grandes, isso duplica storage. Alternativa: ler o binário direto do volume na silver ou usar o tipo FILE BETA.

Perguntas de checagem
  1. Como o pipeline sabe que um arquivo já foi processado?
    Pelo checkpoint da streaming table (Auto Loader/read_files em modo stream).
  2. Gatilho de chegada de arquivo ou agendamento fixo?
    Chegada de arquivo quando a chegada é irregular; agendamento quando há janela conhecida.
  3. O que acontece se um arquivo existente for sobrescrito?
    Depende da configuração; por padrão o Auto Loader não reprocessa arquivos já vistos. Para versionar, use nomes únicos ou trate alterações explicitamente.

Databricks · SQL Editor
-- Chunks prontos para índice de busca (a partir da silver já parseada)
CREATE OR REPLACE TABLE {{CATALOG}}.gold.chunks_busca
TBLPROPERTIES (delta.enableChangeDataFeed = true)   -- exigido para Delta Sync
AS
WITH prepped AS (
  SELECT caminho, ai_prep_search(parsed) AS result
  FROM {{CATALOG}}.silver.documentos_parseados
)
SELECT
  chunk.value:chunk_id::STRING          AS chunk_id,
  chunk.value:chunk_position::INT       AS chunk_position,
  chunk.value:chunk_to_retrieve::STRING AS chunk_to_retrieve,
  chunk.value:chunk_to_embed::STRING    AS chunk_to_embed,
  chunk.value:metadata                  AS metadata,
  prepped.caminho                       AS source_uri
FROM prepped,
LATERAL variant_explode(prepped.result:document.contents) AS chunk;

FATO Credencial da conexão

A credencial usada para criar a conexão do mirroring é usada em todas as consultas. Conexão criada com a conta de um admin expõe tudo o que o admin vê. Use service principal com grants mínimos.

FATO Rede

A página do tutorial ainda diz que o workspace não pode estar atrás de private endpoint, mas a documentação e o anúncio GA mais recentes mostram suporte via VNet data gateway (exige VNet injection e private link no front-end; on-premises gateway não é suportado). Detalhes no M9.

Perguntas de checagem
  1. Por que não há cópia?
    O item espelhado guarda metadados e lê os arquivos Delta via shortcut no storage onde já estão.
  2. Por que é somente leitura?
    A escrita é responsabilidade do Databricks (fonte da verdade); o Fabric só lê.
  3. O grupo leitura tem SELECT na gold no Databricks. Ele já vê a tabela no Fabric?
    Não automaticamente. As permissões do Unity Catalog não atravessam; precisa de workspace role ou OneLake security no Fabric.
  4. Quais três pré-requisitos do lado Databricks?
    Unity Catalog, external data access no metastore, EXTERNAL USE SCHEMA (+ SELECT) para a identidade da conexão. Tabelas em Delta.

PREMISSA Filtros, máscaras e mirroring

Não há garantia documentada de que row filters e column masks do Unity Catalog sejam aplicados no Fabric. Teste: espelhe uma tabela com filtro e consulte com um usuário do grupo leitura. Até confirmar, o desenho seguro é publicar no Fabric só a documentos_consumo, já sem PII.

Lado Fabric e Purview

  1. Fabric · item espelhado · Manage OneLake security
    Crie uma role de leitura com o grupo e só a tabela de consumo. o item Azure Databricks mirrored catalog aceita permissão Read. Lembre: OneLake security atua sobre quem tem acesso de Viewer; Admin/Member/Contributor têm acesso elevado.
  2. Fabric · item · Sensitivity label
    Aplique um rótulo (por exemplo, Confidencial) ao item espelhado e ao relatório. o rótulo acompanha exportações suportadas (Excel, PDF).
  3. Portal Purview · Data loss prevention · Policies · Create · Fabric and Power BI
    Crie uma política em modo de teste que detecte CPF (tipo de informação sensível) nos itens do workspace , com dica de política e alerta. ao atualizar dados, o item ganha um ícone de violação; o alerta aparece em DLP › Alerts. A ação "restrict access" está em preview.
  4. Portal Purview · Audit
    Pesquise atividades do Fabric do dia (abertura do item, consulta, compartilhamento). eventos do Fabric no log de auditoria. Pode levar algum tempo para aparecer.
Lacuna que você deve declarar

Nenhum DLP do Purview inspeciona o conteúdo dos arquivos no Volume do Databricks. Ali a proteção é o grant. Em cliente, isso vai para a matriz de riscos com dono e mitigação.

Perguntas de checagem
  1. Um usuário Contributor no workspace Fabric vê dados fora da role de OneLake security. Por quê?
    Admin, Member e Contributor têm acesso elevado pela permissão Write; OneLake security mira usuários com acesso de leitura.
  2. Onde o DLP do Fabric atua e onde não atua?
    Atua em itens estruturados (lakehouse, warehouse, mirrored, modelos semânticos…). Não atua sobre arquivos no Volume do Databricks.
  3. Por que publicar uma gold sem PII em vez de confiar só em máscaras?
    Porque máscaras do Unity Catalog não têm aplicação garantida no Fabric e o caminho de storage direto contorna RLS/CLM.

Mensagem de 30 segundos

"O Databricks transforma documentos em dados com IA e governa o acesso no Unity Catalog. O Fabric consome esses dados sem cópia. O Purview protege o que chega ao Fabric com rótulos, DLP e auditoria. A lacuna que tratamos por desenho é o arquivo bruto, protegido por permissão e não por DLP."
